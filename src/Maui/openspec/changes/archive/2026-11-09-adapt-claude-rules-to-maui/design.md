# Design

## Context

Правила лежат в `src/Maui/.claude/rules/` и подгружаются как инструкции проекта. Сверка с кодом показала расхождения (см. proposal.md — Why). Существующий код частично нарушает формулировки правил: `Commands.cs` содержит три типа, `GameViewModel` не `sealed`, тесты названы вне шаблона `Should/ShouldNot`, `CanUndo` не имеет префикса `Is`/`Has`.

## Goals / Non-Goals

**Goals:**
- Каждое правило ссылается только на то, что есть в решении, и содержит рабочие команды.
- Правила согласованы с `CLAUDE.md` (корневым и `src/Maui`) и `openspec/config.yaml`.

**Non-Goals:**
- Рефакторинг кода под правила.
- Добавление тестового проекта для `Mobile`, Moq или AutoFixture.
- Правки `CLAUDE.md`, `README.md`, `.editorconfig`.

## Decisions

1. **Правила действуют для нового и изменяемого кода.** Альтернатива — привести код в соответствие сейчас; отвергнута как раздувающая объём. Нарушения существующего кода фиксируются явными оговорками (`Commands.cs`, имена тестов).
2. **Moq и AutoFixture убираем.** `Core` без внешних зависимостей, мокать нечего; пакеты не подключены. Возвращаются вместе с тестовым проектом для `Mobile` по согласованию.
3. **Комментарии и XML-doc на русском.** Так в коде и в `CLAUDE.md`; правило «Summary required» в `workflow.md` приведено в соответствие.
4. **`sealed` допустим для `partial`-моделей.** CommunityToolkit.Mvvm работает с `sealed partial`; существующий `GameViewModel` не трогаем.
5. **Async, `CancellationToken`, `TimeProvider` оставляем как условный раздел.** В коде нет ни того, ни другого; раздел помечен «когда появится», чтобы не плодить правки при появлении таких задач.
6. **Версия приложения:** источник — `ApplicationDisplayVersion`/`ApplicationVersion` в `Mobile.csproj`; упоминания в `README.md` и `docs/rustore-publishing.md` обновляются, если есть. Файлы `README.ru.md`, `build/release-notes.md` в правилах не упоминаются, поскольку их нет.
7. **Блок про OpenSpec — в `workflow.md`:** изменения поведения проходят `/opsx:propose` → `/opsx:apply` → `/opsx:archive`, согласно `openspec/config.yaml`.
8. **Дублирование с `CLAUDE.md`** (граница `Core`/`Mobile`, запрет коммитить ключи) сохраняем: правила должны быть самодостаточными.

## Risks / Trade-offs

- [Правила разойдутся с кодом при его развитии] → пересматривать правила при добавлении нового слоя (сообщения, диалоги, тестовый проект `Mobile`).
- [Оговорки «в новом коде» ослабляют контроль] → нарушения существующего кода фиксируются в явном списке и снимаются отдельными changes.
- [Сборка `Mobile` недоступна без нагрузки `maui-android`] → правило требует явно сообщить, что сборка не выполнена, а не молча её пропускать.
