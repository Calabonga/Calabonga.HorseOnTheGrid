## Рекомендации по языку C# и стилю

### Современный синтаксис
- Используй file-scoped namespaces и глобальные `using` (`ImplicitUsings` включены).
- Используй primary constructors там, где они уместны; для сервисов с `private readonly` полями допускается классический конструктор (как в существующем коде).
- Используй target-typed `new()` при создании экземпляров, когда тип очевиден из контекста.

### Безопасность нулевых значений
- Ссылочные типы, допускающие null, включены (`<Nullable>enable</Nullable>`).
- Не используй `!` для подавления предупреждений, если это не задокументировано комментарием.

### Неизменяемость
- Существующие DTO-классы не переписывай ради стиля, только при необходимости изменения.

### Стиль написания кода
- Используй `var`, только если тип очевиден из правой части выражения.
- Применяй `nameof()` вместо строковых литералов для имён методов, свойств, классов и событий.
- Применяй `is` и `as` вместо приведения типов.
- Свойства типа `bool` называй с префиксом `Is` или `Has` (например `IsGitLabReady`, `HasChanges`).
- Используй `switch`-выражения вместо `switch`-операторов и цепочек `if-else`, когда это возможно.
- Используй `try-catch` только для ожидаемых ошибок, а не для управления потоком выполнения.
- Явно указывай модификаторы доступа для всех членов класса.
- Методы и свойства по умолчанию `private`, если они не предназначены для использования вне класса.
- Классы по умолчанию `sealed`, если они не предназначены для наследования.
- Используй statement body вместо expression body для методов и свойств, если в них больше одной строки кода.

### Порядок членов класса
1. `private readonly` поля и константы.
2. Конструкторы.
3. Публичные методы и свойства.
4. Приватные (вспомогательные) методы.
5. `override`-методы.
6. `Dispose()` / `DisposeAsync()` — в самом конце класса.

### MAUI / MVVM
- Используй `CommunityToolkit.Mvvm` (`[ObservableProperty]`, `[RelayCommand]`), ViewModel наследуй от `Core.Base.ViewModelBase`.
- Взаимодействие между ViewModel — через сообщения `WeakReferenceMessenger` (`Core/Messaging`), а не прямые ссылки.
- Код в `*.xaml.cs` (code-behind) — только логика представления; бизнес-логика живёт в ViewModel и исполнителях.
- Новые View, ViewModel, диалоги и сервисы регистрируй в `Core/DependencyContainer.cs`.
- Обращения к UI из фонового потока — только через `Dispatcher`.

### Асинхронный поток
- Добавляй суффикс `Async` ко всем именам асинхронных методов.
- Всегда передавай `CancellationToken` в асинхронные методы.
- `ConfigureAwait(false)` используй в логике, не зависящей от UI-потока (исполнители, построение отчётов); в ViewModel и code-behind — не используй.
- `async void` допускается только в обработчиках событий.

### Обработка ошибок
- Используй подход Fail Fast.
- Ошибки HTTP-запросов к GitLab фиксируй через `request.SetError(...)` и уведомляй UI сообщением `ExceptionNotificationMessage`, как в существующих исполнителях (`Core/Executors/GitLab`).
- Не глотай исключения молча: логируй через `ILogger` / Serilog.

### Время/Часы
- Внедряй и используй `TimeProvider` вместо прямого вызова `DateTime.UtcNow` / `DateTime.Now` в новом коде.
