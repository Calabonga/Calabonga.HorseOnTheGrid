## Рекомендации по языку C# и стилю

Правила относятся к новому и изменяемому коду. Существующий код ради стиля не переписывай.

### Архитектура
- `Core` не ссылается на MAUI и платформенные API. Любая правка правил игры — только там и с тестом.
- `Mobile` отображает состояние: ViewModel не дублирует правила хода и обращается к ядру через `Game`.
- Состояние ядра меняется только через `Game`; `Board.Visit/Unvisit/Clear` — `internal`.

### Современный синтаксис
- File-scoped namespaces и глобальные `using` (`ImplicitUsings` включены).
- Primary constructors там, где уместны; для классов с `private readonly` полями допустим классический конструктор (как в `GameViewModel`).
- Target-typed `new()`, когда тип очевиден из контекста.

### Безопасность нулевых значений
- `<Nullable>enable</Nullable>`.
- Не используй `!` для подавления предупреждений без комментария-обоснования.

### Стиль написания кода
- `var` — только если тип очевиден из правой части (`new`, явное приведение, `GetRequiredService<T>()`).
- `nameof()` вместо строковых литералов для имён членов и типов.
- `is` и `as` вместо приведения типов.
- Свойства `bool` называй с префиксом `Is`/`Has` (`IsGameOver`). Исключение — предикаты-действия вида `CanUndo`/`CanMoveTo`.
- `switch`-выражения вместо `switch`-операторов и цепочек `if-else`, где это читаемо.
- `try-catch` — только для ожидаемых ошибок, не для управления потоком.
- Явные модификаторы доступа; по умолчанию `private`.
- Классы по умолчанию `sealed`. Для `partial`-моделей с CommunityToolkit.Mvvm `sealed` допустим.
- Statement body вместо expression body, если в члене больше одной строки.
- Комментарии и XML-doc — на русском языке.

### Порядок членов класса
1. `private readonly` поля и константы.
2. Конструкторы.
3. Публичные методы и свойства.
4. Приватные методы.
5. `override`-методы.
6. `Dispose()` / `DisposeAsync()` — в конце.

### MAUI / MVVM
- CommunityToolkit.Mvvm: `[ObservableProperty]`, `[RelayCommand]`, `[NotifyPropertyChangedFor]`; модели — `partial`, наследуются от `ObservableObject`.
- Привязки компилируются: в XAML указывай `x:DataType`.
- Вид клетки переключай `DataTrigger` по `CellState`, а не логикой в code-behind.
- Code-behind (`*.xaml.cs`) — только логика представления (например, квадратность поля).
- Новые страницы, модели и сервисы регистрируй в `MauiProgram.cs`.
- Настройки храни через `IPreferences`; ключи выноси в константы.
- Обращения к UI из фонового потока — через `Dispatcher`/`MainThread`.
- Приложение только в портрете и светлой теме: не добавляй зависимость от тёмной темы.

### Асинхронный поток (когда появится async-код)
- Суффикс `Async` у асинхронных методов, `CancellationToken` — параметром.
- `ConfigureAwait(false)` — в `Core` и коде, не зависящем от UI; в ViewModel и code-behind не используй.
- `async void` — только в обработчиках событий.

### Обработка ошибок и логирование
- Fail Fast: нарушенные инварианты ядра — исключение (как в `Board.Unvisit`), недопустимый ход — `false` из `TryMove`.
- Не глотай исключения молча: логируй через `ILogger<T>`.
- Логирование — `Microsoft.Extensions.Logging.Debug` только в `DEBUG`.

### Время (когда появится логика, зависящая от времени)
- Внедряй `TimeProvider` вместо `DateTime.Now`/`UtcNow`.
